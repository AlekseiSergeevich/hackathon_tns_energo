# 001. В файле 12 у 41 % строк вместо ЛС стоит `#N/A`

| | |
|---|---|
| Статус | ждём заказчика |
| Найдено | 2026-11-03, Алексей, при сверке числа строк в журналах мер (ML-1) |
| Где | `Материалы к кейсу/12 Заявление о выдаче судебного приказа ХК.xlsx` |
| Влияет на | машина стадий (S4–S5), признаки ML по судебным мерам, отчёт о качестве |
| Ответственный | Алексей (запрос заказчику), Женя (валидатор DATA-2) |
| Связано | ORG-5, DATA-2, DATA-3, RULE-3; риск D5 в `docs/plan_2026-11-01.md` |

## Что не так

В файле 14 232 строки данных. У **5 842 из них (41 %)** в колонке «ЛС» не номер, а ошибка Excel `#N/A`, при этом дата заполнена. Похоже, при выгрузке у заказчика не сработала формула подстановки номера ЛС (вроде ВПР).

Все такие строки идут подряд в конце листа: строки 1–8 390 с номером ЛС, с 8 391-й и до конца — `#N/A`. Объединённых ячеек нет, так что восстановить номер по соседним строкам нельзя.

## Примеры

Граница в файле (номера строк данных от 0, без двух строк шапки; в Excel номер строки на 3 больше):

```
 №      ЛС       Дата
 8386   147017   2026-02-04
 8387   147017   2025-02-24
 8388   147017   2025-05-30
 8389   147017   2026-02-04
 8390   NaN      2025-08-28     ← в Excel: A8393 = '#N/A' (тип ячейки «ошибка»)
 8391   NaN      2025-09-25
 8392   NaN      2025-12-22
 ...
```

Строки без ЛС есть во всех месяцах:

| 2025-01 | 02 | 03 | 04 | 05 | 06 | 07 | 08 | 09 | 10 | 11 | 12 | 2026-01 | 02 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 257 | 274 | 172 | 433 | 311 | 657 | 460 | 483 | 806 | 408 | 417 | 456 | 280 | 428 |

В остальных девяти файлах мер (04–11, 13) строк без ЛС нет.

## Как воспроизвести

```python
import openpyxl
import pandas as pd

path = "Материалы к кейсу/12 Заявление о выдаче судебного приказа ХК.xlsx"

raw = pd.read_excel(path, header=None).iloc[2:, :2].reset_index(drop=True)  # строки 1–2: название и «ЛС | Дата»
raw.columns = ["ls", "date"]
ls = pd.to_numeric(raw["ls"], errors="coerce")
print("строк данных:", len(raw))                                    # 14232
print("без ЛС:", ls.isna().sum())                                    # 5842
print("первая строка без ЛС:", ls.isna().idxmax(),                    # 8390
      "| последняя с ЛС:", ls.last_valid_index())                     # 8389
print(raw.iloc[8386:8393])

ws = openpyxl.load_workbook(path).active
cell = ws["A8393"]
print("ячейка A8393:", repr(cell.value), "тип:", cell.data_type)    # '#N/A' тип: e (ошибка)
print("объединённых ячеек:", len(ws.merged_cells.ranges))            # 0

months = pd.to_datetime(raw.loc[ls.isna(), "date"]).dt.to_period("M")
print(months.value_counts().sort_index())
```

## Почему это важно

- **Стадии (Аня).** Машина стадий берёт дату заявления в суд (`court_application_date`). У ЛС, чьи заявления попали в `#N/A`, стадия S4/S5 не определится: программа будет считать, что в суд по ним не обращались, и может предложить меры, которые уже не нужны.
- **ML.** Признаки `n_court_application_6m` и `months_since_court_application` занижены. Влияние небольшое: судебные меры есть у ~9 % должников в выборке.
- **Лимит.** С номерами ЛС остаётся ~300 заявлений в месяц при лимите 400. Возможно, реальная загрузка лимита выше, чем видно по данным.
- **Хакатонный код** терял эти строки так же молча (`dropna` в `read_measure_events`).

## Что делаем сейчас

`tns/ml/proto_panel.py`, функция `_read_measure_file`: строки без ЛС или даты пропускаются, в лог пишется предупреждение «… 5 842 из 14 232 строк без ЛС или даты (например, #N/A в выгрузке), они пропущены».

## Что нужно, чтобы закрыть

1. **Заказчику (ORG-5):** прислать файл 12 заново, с номерами ЛС во всех строках.
2. **Жене (DATA-2, DATA-3):** в валидаторе проверять долю строк без ЛС в каждом файле (например, > 1 % — предупреждение, > 10 % — ошибка) и выводить её в отчёт о качестве.
3. **Ане (RULE-3):** пока файл не исправлен, учитывать, что судебная история неполная.
