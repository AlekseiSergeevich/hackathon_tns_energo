# Скрипт `run_kprototypes_segmentation.py` и выход `kprototypes_segment_profile.csv`

## Назначение

Скрипт реализует **п. 2.1 плана** (сегментация должников): кластеризация **K-Prototypes** по таблице признаков [`output/kprototypes_features.csv`](../output/kprototypes_features.csv), собранной [`scripts/build_kprototypes_features.py`](../scripts/build_kprototypes_features.py). Подход: смешанные **числовые** (после стандартизации) и **категориальные** признаки; алгоритм в пакете `kmodes` (класс `KPrototypes`, [репозиторий](https://github.com/nicodv/kmodes)).

Вход: один CSV с признаками. Выход: метки сегмента на каждое ЛС, агрегированный **профиль** по сегментам и JSON с параметрами запуска.

---

## Зависимости

Установка из корня репозитория:

```bash
pip install -r requirements.txt
```

Нужны: `pandas`, `numpy`, `scikit-learn`, `kmodes` (версия с PyPI, см. `requirements.txt`).

## Запуск

```bash
python scripts/run_kprototypes_segmentation.py
```

| Аргумент | По умолчанию | Смысл |
|----------|---------------|--------|
| `--input-csv` | `output/kprototypes_features.csv` | Таблица признаков |
| `--n-clusters` | `6` | Число кластеров K |
| `--fit-sample` | `50000` | Сколько строк участвуют в **fit**; `0` — вся выборка (дольше) |
| `--random-state` | `42` | Воспроизводимость (подвыборка, инициализация) |
| `--n-init` | `1` | Число запусков с разными сидов (лучший по cost) |
| `--max-iter` | `30` | Максимум итераций k-prototypes |
| `--n-jobs` | `1` | Параллелизм по `n_init` (`-1` — все ядра, если среда позволяет) |
| `--out-labels` | `output/kprototypes_labels.csv` | `ls` + `segment` |
| `--out-profile` | `output/kprototypes_segment_profile.csv` | Профили сегментов (см. ниже) |
| `--out-meta` | `output/kprototypes_run_meta.json` | Списки колонок, `gamma`, `cost`, `n_iter` и др. |

**Важно по логике:**

- Из матрицы признаков **исключаются** `ls`, `snapshot_month`, `asof_date` (идентификатор и сырые даты; сезонность уже отражена в `month_sin` / `month_cos`).
- **Числовые** колонки: все остальные, кроме фиксированного списка категориальных (совпадает с `fill_missing_for_kprototypes` в `build_kprototypes_features.py`).
- **Стандартизация** (`StandardScaler`) применяется к числовому блоку **на полной** выбранной таблице; затем при необходимости из неё берётся случайная подвыборка только для `fit`, а `predict` выполняется **для всех** строк.
- Категориальные поля в одном массиве идут **после** числовых (требование `kmodes`).

## Файлы на выходе

| Файл | Содержание |
|------|------------|
| `kprototypes_labels.csv` | Каждому `ls` присвоен целочисленный `segment` (0 … K−1) |
| `kprototypes_segment_profile.csv` | Сводка по сегментам для интерпретации (см. следующий раздел) |
| `kprototypes_run_meta.json` | Метаданные: пути, число признаков, `fit_sample_size`, `gamma`, ит. |

Номера сегментов **условны** (зависят от инициализации и данных); сравнивать смысл лучше по **профилю** и медианам, а не по номеру.

## Расшифровка колонок `kprototypes_segment_profile.csv`

Строка = один сегмент (кластер). Колонки:

| Колонка | Как считается | Смысл |
|---------|----------------|--------|
| `segment` | Номер кластера, 0 … K−1 | Идентификатор в `kprototypes_labels.csv` |
| `n` | Число ЛС в сегменте | Объём сегмента |
| `share` | `n` / N | Доля от всей выборки (сумма по строкам = 1) |
| `median_DZ_current` | Медиана `DZ_current` по ЛС сегмента | Типичный размер **текущей** задолженности (руб., по определению в спецификации признаков) |
| `median_payment_ratio_12m` | Медиана `payment_ratio_12m` | Отношение оплачено/начислено за 12 мес. (см. [`kprototypes_features_spec.md`](kprototypes_features_spec.md)); ближе к 1 — **выше** дисциплина по оплатам в окне |
| `median_log1p_DZ_current` | Медиана `log(1 + max(DZ,0))` | Долг на лог-шкале; удобен для сжатия выбросов, согласуется с масштабом ДЗ |
| `median_n_measures_12m` | Медиана `n_measures_12m` | Сколько **всего** мер воздействия (всех типов) приходится на 12 мес. — интенсивность взаимодействия с абонентом |
| `mode_stage_reached` | Мода значения `stage_reached` | Наиболее частая **достигнутая стадия** процедуры (инфо / уведомление об ограничении / … / «Суд») внутри сегмента; `Unknown` — если в сырых данных нет устойчивой стадии или заполнялось так при сборке фич |

Профиль строится **по исходным** колонкам из `kprototypes_features.csv` (медианы/мода), а не по стандартизованным Z-признакам, чтобы цифры читались в «рублях и долях».

## Пример расшифровки (актуальная версия `output/kprototypes_segment_profile.csv`)

Ниже — ориентировочная **бизнес-интерпретация** для прогона с K=6 и типичными настройками (подвыборка для `fit` 50k, `random_state=42`). Цифры соответствуют последней сохранённой таблице профиля; при другом K или сидах распределения изменятся.

| segment | n / доля | Чтение |
|---------|-----------|--------|
| **0** | ~3.3k (~2.4%) | **Высокая ДЗ**, мода стадии **«Суд»**; `median_payment_ratio_12m` ≈ 0 — в типичной истории 12 мес. почти **нет** оплат в доле к начислениям; **много мер** за год (медиана ~10) — тяжёлая, судебно-зрелая подгруппа. |
| **1** | ~7.4k (~5.4%) | Средняя/высокая ДЗ, **уведомление об ограничении** как типичная стадия; `payment_ratio_12m` **высокий** (около 0.96) — **платят относительно дисциплинированно**, при этом `n_measures_12m` **высокий** (около 17) — **активно обрабатываемые** клиенты на стадии до/после ограничения. |
| **2** | ~1.7k (~1.3%) | **Очень высокая** ДЗ; стадия чаще **уведомление об ограничении**, **меньше** мер в год, чем в сегменте 0/1 — **узкий** «крупные долги / не суд» (по срезу). |
| **3** | ~84k (~62%) | **Крупный** сегмент: **невысокая** типичная ДЗ, `payment_ratio_12m` **близок к 1** — **базовая** масса с **относительно ровной** оплатой; `mode_stage_reached` **Unknown** — стадия по журналу мер не классифицируется/не заполнена; умеренная частота мер. |
| **4** | ~26k (~19%) | **Нулевая** медиана `DZ_current` и `log1p` — **нет** текущей просрочки в медиане; `payment_ratio_12m` ниже, чем у «топ-дискиплинов», стадия **Unknown** — условно **«мало долга / отработано»** или **переходные** балансы на срезе. |
| **5** | ~13.5k (~10%) | Средняя ДЗ, **самая низкая** по медиане `n_measures_12m` (около 2); мода **«Информирование»** — **ранняя** стадия, **низкое** давление мер, при этом `payment_ratio_12m` **высокий** — **ранние / мягкие** абоненты. |

**Оговорка:** K-Prototypes **не** гарантирует бизнес-названия; интерпретация — по агрегатам. Для презентации можно **переименовать** сегменты (например, «Суд-фокус», «Массовый исправно платит») и зафиксировать правило в отчёте/ноутбуке.
