# Веб-приложение: сначала на своём компьютере, потом на сервере

## Контекст

Заказчик хочет веб-приложение: бэкенд на одном сервере во внутренней сети ТНС Энерго, доступ по ссылке у определённых сотрудников. Прежде чем идти к ИТ заказчика, нужно собрать и запустить это приложение **на своём компьютере (macOS)**: открыть в браузере, войти, загрузить данные, построить план, скачать результат.

Принцип: локальная версия — это **то же приложение**, что пойдёт на сервер, только с другими настройками. Нельзя делать отдельную «упрощённую» версию, которую потом придётся переписывать.

| | Свой компьютер (этап 1) | Сервер ТНС (этап 2) |
|---|---|---|
| Адрес | `http://127.0.0.1:8000` | `https://tns-plan.corp.local` |
| Вход | свои логины (пароль в SQLite) | Active Directory через LDAP |
| HTTPS | не нужен | nginx + сертификат внутреннего центра сертификации |
| Запуск | `python web.py` | Docker-образ или системная служба |

Отличия только в `configs/settings.yaml` (раздел `web:`) и переменных окружения.

Что уже есть:
- `run.py` и `tns/pipeline.py`: сервер запускает план отдельным процессом `python run.py --month … --data … --out …` (коды возврата 0/1). Шаги 5–9 (правила, ML, аллокатор) ещё не готовы и пропускаются, поэтому пока результат — parquet-файлы (`ls_info`, `measure_events`, `panel`);
- `tns/logs.py` (SVC-6): у каждого запуска свой журнал; строки «Шаг N/9» служат прогрессом; тексты ошибок «что не так + что сделать»;
- `tns/data/loaders.py`: имена файлов 01–14; `tests/conftest.py`: мини-данные для тестов.

## Этап 1. Запуск на своём компьютере

Каждый шаг заканчивается тем, что можно открыть в браузере и проверить руками.

### Шаг 1. Подготовка (0,5 дня)
- Поставить в `.venv` пакеты fastapi, uvicorn, jinja2, python-multipart, argon2-cffi. Записать их в `requirements.txt` с точными версиями.
- Добавить в `.gitignore` папку `storage/` (там будут база, загруженные данные и результаты запусков).

### Шаг 2. Каркас: страница открывается (1 день)
- `tns/web/app.py` (FastAPI), `tns/web/templates/base.html`, `tns/web/static/style.css`, точка запуска `web.py` в корне (с той же проверкой «не установлена библиотека», что в `run.py`).
- Раздел `web:` в `configs/settings.yaml`: host `127.0.0.1`, port `8000`, storage_dir `storage`, auth `local`, max_upload_mb, keep_days.
- **Проверка:** `python web.py` → в браузере `http://127.0.0.1:8000` видна главная страница, `/health` отвечает `ok`.

### Шаг 3. Вход и роли (2 дня)
- SQLite-база `storage/app.db`, таблица `users`. Команда `python -m tns.web.users add <логин> --role admin` для создания пользователей.
- Страница входа, сессия в cookie, выход, роли: администратор, аналитик, наблюдатель. Без входа все страницы перенаправляют на страницу входа.
- Проверка пароля вынесена в отдельный модуль с общим интерфейсом (`tns/web/auth.py`: `local` сейчас, `ldap` на этапе 2), чтобы потом заменить вход без переделки остального.
- **Проверка:** создать admin и viewer, войти каждым, убедиться, что viewer не видит кнопку «Запустить» и не может вызвать её напрямую.

### Шаг 4. Данные: загрузка и проверка (2 дня)
- Таблица `datasets`. Страница «Данные»: загрузить zip или несколько файлов 01–14 в `storage/datasets/<id>/`. Показать, какие файлы найдены и каких нет. Ограничить размер и разрешённые имена.
- Для удобства на своём компьютере и для варианта «общая папка» на сервере — второй способ: выбрать набор из разрешённой папки (настройка `web.data_roots`, локально нужно указать `Материалы к кейсу`), чтобы не загружать 100+ МБ при каждом тесте.
- Кнопка «Проверить»: отдельный процесс выполняет шаги 1–3 пайплайна. Итог и ошибки показываются текстами SVC-6.
- **Проверка:** загрузить `Материалы к кейсу` (zip) → «проверка пройдена»; убрать файл 06 → понятная ошибка с советом.

### Шаг 5. Запуск плана: очередь, прогресс, история (2–3 дня)
- Таблица `runs`. Кнопка «Сформировать план» (выбор месяца из месяцев в данных) ставит запуск в очередь. Один исполнитель в фоне запускает `run.py` через `subprocess`, папка `--out` — `storage/runs/<id>/`, журнал — туда же (`TNS_LOG_DIR`).
- Страница запуска показывает «Шаг N/9» (опрос раз в 2 секунды), кнопку «Остановить» и итог. При ошибке — «что не так / что сделать».
- История запусков: кто, когда, месяц, данные, статус. После перезапуска `web.py` незавершённые запуски помечаются «прерван».
- **Проверка:** запустить 2026-02 на настоящих данных и дождаться «готово»; запустить два раза подряд — второй ждёт в очереди; остановить запуск посередине.

### Шаг 6. Результаты (1–2 дня)
- На странице запуска список файлов и кнопки скачивания. Пока это parquet, поэтому сразу отдавать и Excel-версию (конвертировать при скачивании). Когда Аня сделает реестры (SVC-3), здесь появятся они.
- Поиск по номеру ЛС: строка панели (долг, срок просрочки, результат). Объяснение меры добавится после движка правил.
- Журнал действий `audit`: вход, загрузка, запуск, скачивание.
- **Проверка:** скачать панель за 2026-02, найти любой ЛС из `overdue_check.xlsx`, сверить цифры.

### Шаг 7. Тесты (параллельно с шагами 2–6, итого ~2 дня)
- `tests/test_web.py` на `fastapi.testclient.TestClient` и мини-данных из `tests/conftest.py`. Проверить:
  - вход и роли, доступ к чужому файлу запрещён;
  - загрузку (нет файла, имя `../x.xlsx`, превышение размера);
  - запуск (успешный, ошибка шага с текстом SVC-6, очередь, остановку);
  - записи в журнале действий.
- **Проверка:** `.venv/bin/python -m pytest` проходит весь.

### Шаг 8. Репетиция сервера на своём компьютере (1–2 дня, по желанию до разговора с ИТ)
- `Dockerfile` и `docker-compose.yml` (приложение + nginx с самоподписанным сертификатом). Запуск через Docker Desktop: `docker compose up` → `https://localhost`.
- Открыть с телефона или второго ноутбука в домашней сети. Это то же, что «доступ по ссылке» внутри сети ТНС.
- **Проверка:** всё из шагов 3–6 работает в контейнере. Архив образа (`docker save`) собирается — его потом и повезём заказчику.

Итого этап 1: около 11–14 рабочих дней. Результат — демо для Алексея и заказчика на своём ноутбуке.

## Этап 2. Перенос на сервер ТНС Энерго (после ответов ИТ)
- Ответы ИТ: ОС, разрешён ли Docker, есть ли интернет на сервере, Active Directory и группа доступа, DNS-имя, сертификат, разрешённые подсети.
- Вход через LDAP (`auth: ldap`, роль по группе AD), 1–2 дня.
- HTTPS с сертификатом заказчика, правило межсетевого экрана, резервные копии `storage/`, автоудаление старых данных (`keep_days`).
- Установка из архива образа без интернета, инструкция администратора и пользователя (SVC-8), пилот с 2–3 сотрудниками.

## Проверка всего этапа 1
- `.venv/bin/python -m pytest` проходит.
- `python web.py`: вход аналитиком → данные `Материалы к кейсу` → «Проверить» → «Сформировать план» за 2026-02 → видно прогресс → скачан результат. Наблюдатель видит результат, но не может запустить план. Подставленные ошибки показываются с советом «что сделать».
