# Спецификация признаков: `build_kprototypes_features.py`

Документ описывает **откуда берётся** и **как считается** каждая колонка итоговой таблицы, которую строит [`scripts/build_kprototypes_features.py`](../scripts/build_kprototypes_features.py).

---

## Временной контекст (параметры расчёта)

Эти величины задают окна агрегации для **всех** признаков, зависящих от времени.

| Параметр | Откуда | Как задаётся |
|----------|--------|--------------|
| `snapshot_month` (месяц среза T) | ОСВ `02` | Если `--snapshot-month` не передан: **1-е число максимального месяца** в расплавленной ОСВ; иначе — переданная дата, нормализованная к началу месяца (`build_context`). |
| `asof_date` | Производное от T | **Последний день месяца T** (`snapshot_month + MonthEnd(0)`). |
| Окно 12 мес. | Производное | С `window12_start = T − 11 месяцев` по **T включительно**. |
| Окно 6 мес. | Производное | С `window6_start = T − 5 месяцев` по **T включительно**. |
| Окно 3 мес. | Производное | С `window3_start = T − 2 месяца` по **T включительно**. |

**Множество ЛС** в итоговой таблице — **объединение** всех `ls`, встречающихся в файлах `01`, `02`, `03`, `04–13` (`build_features`).

## Таблица колонок выхода

| Колонка | Источник файла(ов) | Поля / события | Как считается |
|---------|-------------------|----------------|---------------|
| `ls` | `01`, `02`, `03`, `04–13` | `ЛС` / `Номер` | Нормализация в целое `Int64` (`normalize_ls`). |
| `has_phone` | `01` | `Наличие телефона` | Да/Нет → `Yes`/`No`, иначе `Unknown` (`yes_no_to_label`). |
| `has_ebill` | `01` | `электронная квитанция` | То же. |
| `is_gasified` | `01` | `Газификация дома` | То же. |
| `has_benefits` | `01` | `Наличие льгот` | То же. |
| `not_residing` | `01` | `не проживает` | То же. |
| `remote_disconnect_possible` | `01` | `Возможность дистанционного отключения` | То же. |
| `room_type` | `01` | `ЧД`, `МКД`, `Общежитие` | Одна категория: приоритетно первая из совпавших меток `Yes` → `ЧД` / `МКД` / `Общежитие`, иначе `Unknown` (`np.select`). |
| `meter_installation` | `01` | `Установка Тамбур`, `Установка опора`, `Установка в квартире/доме`, `Установка лестничкая клетка` | Аналогично: одна категория из четырёх или `Unknown`. |
| `settlement_type` | `01` | `Город` | Если `Город` = Да → `Город`, иначе `Село/Прочее`. |
| `DZ_current` | `02` | `СЗ на начало` | Значение на месяц **`snapshot_month`**: для ЛС строка с `month == T`, поле `sz_start` → `DZ_current`. |
| `avg_accrual_12m` | `02` | `Начислено` | Среднее `accrual` по ЛС за **12 мес.** до T включительно. |
| `avg_payment_12m` | `02` | `Оплачено` | Среднее `paid` за те же 12 мес. |
| `months_with_full_payment_12m` | `02` | `Начислено`, `Оплачено` | За 12 мес.: число месяцев, где **`paid >= accrual`**. |
| `months_with_zero_payment_12m` | `02` | `Оплачено` | За 12 мес.: число месяцев с **`paid <= 0`**. |
| `max_consecutive_nonpayment` | `02` | `Оплачено` | За 12 мес.: максимальная длина подряд месяцев с **`paid` NaN или ≤ 0**. |
| `tenure_months` | `02` | `month` | За 12 мес.: **`nunique` месяцев** в окне (не полная история ЛС с начала выгрузки). |
| `payment_ratio_12m` | `02` | `Начислено`, `Оплачено` | \(\sum paid / \sum accrual\) за 12 мес.; деление на 0 → NaN; **clip [0, 2]**. |
| `payment_ratio_3m` | `02` | То же | Аналогично за **3 мес.**; **clip [0, 2]**. |
| `dz_trend_slope_6m` | `02` | `СЗ на начало` | За 6 мес.: наклон линейной регрессии `sz_start` по порядку месяцев (`linear_slope` / `polyfit`). |
| `dz_volatility_6m` | `02` | `СЗ на начало` | За 6 мес.: **стандартное отклонение** `sz_start` с `ddof=0`. |
| `debt_to_accrual_ratio` | `02` | `DZ_current`, `avg_accrual_12m` | `DZ_current / avg_accrual_12m`; ноль в знаменателе → NaN. |
| `log1p_DZ_current` | `02` | `DZ_current` | `log(1 + max(DZ_current, 0))`. |
| `payments_count_12m` | `03` | строки оплат | Число платежей с `payment_date` от начала **12-месячного окна** до **`asof_date`** включительно. |
| `median_payment_amount_12m` | `03` | `Сумма` | Медиана `amount` (после `parse_money`) за то же окно. |
| `days_since_last_payment` | `03` | `Дата оплаты` | **`asof_date − max(payment_date)`** в днях по оплатам в окне 12 мес. |
| `payment_regularity` | `03` | `Дата оплаты` | Если оплат **≥ 3**: интервалы в днях между соседними оплатами → `std` → **`log1p(1 / (std + 1))`**; иначе NaN. |
| `dominant_payment_method` | `03` | `Способ оплаты` | **Мода** `payment_method` за 12 мес.; если моды нет → `Unknown`. |
| `n_measures_12m` | `04–13` | все меры | Число **всех** событий мер у ЛС в окне **12 мес.** по `event_date`. |
| `n_autodial_12m` | `04` | автодозвон | Счётчик `measure == "autodial"`. |
| `n_email_12m` | `05` | e-mail | `measure == "email"`. |
| `n_sms_12m` | `06` | СМС | `measure == "sms"`. |
| `n_operator_calls_12m` | `07` | обзвон оператором | `measure == "operator_call"`. |
| `n_claims_12m` | `08` | претензия | `measure == "claim"`. |
| `n_visits_12m` | `09` | выезд | `measure == "visit"`. |
| `n_restriction_notifications_12m` | `10` | уведомление об ограничении | `measure == "restriction_notice"`. |
| `n_restrictions_12m` | `11` | ограничение | `measure == "restriction"`. |
| `n_court_applications_12m` | `12` | заявление о суд. приказе | `measure == "court_application"`. |
| `n_court_results_12m` | `13` | получение ИЛ/приказа | `measure == "court_result"`. |
| `days_since_last_measure` | `04–13` | все меры до `asof_date` | **`asof_date − max(event_date)`** по событиям с датой ≤ `asof_date` (**не** ограничено 12 мес.). |

## Постобработка (`fill_missing_for_kprototypes`)

| Шаг | Что делает |
|-----|------------|
| Категориальные колонки из фиксированного списка (`has_phone`, …, `ever_in_court`) | Пропуски → строка **`Unknown`**. |
| Все остальные колонки кроме `ls` | `pd.to_numeric`, пропуски → **медиана по столбцу**. |

---

## Нюансы интерпретации

1. **ОСВ (`02`)** читается с двухстрочной шапкой; метрики нормализуются по алиасам (`СЗ на начало`, `Начислено`, `Оплачено` / `Опалачено` и дубликаты колонок в последнем месяце).
2. **`tenure_months`** — число **уникальных месяцев внутри 12-месячного окна**, а не длина всей истории ЛС в выгрузке.
3. **`payment_ratio_*` > 1** возможно при суммарных оплатах выше суммарных начислений за окно (погашение долга, переплата и т.д.); верхняя граница **2** — намеренное ограничение выбросов для кластеризации.
4. **`response_rate_*`**: любая оплата в окне 14 дней после события считается «откликом»; **не** доказывается причинная связь с конкретной мерой. Если у ЛС не было событий нужного типа в окне, до заполнения пропусков будет NaN, затем — **медиана по столбцу** (для строгой семантики часто задают `0.0` отдельно).

## Запуск скрипта

```bash
python scripts/build_kprototypes_features.py \
  --data-dir "Материалы к кейсу" \
  --output-csv output/kprototypes_features.csv \
  --output-parquet output/kprototypes_features.parquet
```

Опционально: `--snapshot-month 2026-02-01` для фиксированного месяца среза.
